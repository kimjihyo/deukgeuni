# 구조: 두뇌와 기억

득근이는 **두뇌**(이 레포)와 **기억**(사용자 데이터)을 나눈다. LLM 자체는 아무것도 기억하지 않는다. 매 대화마다 두뇌와 기억을 다시 읽어서 이어간다.

```
            ┌───────────── 두뇌: 이 레포 (모든 사용자 공통, 공개) ─────────────┐
            │ AGENTS.md · skills/ · docs/ · scripts/wl.py                     │
            └─────────────────────────────────────────────────────────────────┘
                                    │ 읽기
 사용자 ⇄ 실행 환경(채팅 앱 / 텔레그램 봇 / 슬랙 봇 / 코딩 에이전트) ⇄ LLM
                                    │ wl.py로 읽기·쓰기, Markdown 편집
            ┌──────────── 기억: 사용자 데이터 폴더 (사용자별, 비공개) ────────────┐
            │ 장기 기록   exercises / sessions / sets  (csv·jsonl·sqlite·DB)     │
            │ 코칭 상태   status.md · profile.md · blocks/ · history.md          │
            └─────────────────────────────────────────────────────────────────┘
```

## 기억의 세 층

| 층 | 무엇 | 어디 | 누가 관리 |
| --- | --- | --- | --- |
| 장기 기록 | 세트·세션·운동 사전 | 데이터 폴더, `wl.py`로만 접근 | 에이전트 (`skills/log-workout`) |
| 코칭 상태 | 현재 블록, 다음 세션, 미해결 질문, 사용자 규칙 | 데이터 폴더의 Markdown | 에이전트가 기록·계획 후 갱신 |
| 대화 맥락 | 최근 몇 개 메시지 ("그거 RPE 9였어" 같은 이어지는 말) | 실행 환경 | 채팅 앱은 자동, 봇은 직접 보관 |

- 대화가 끊기거나 모델·플랫폼이 바뀌어도 **장기 기록과 코칭 상태**만 있으면 이어서 코칭할 수 있다. 그래서 "다음에 할 것"은 반드시 `status.md`에 적는다
- 대화 맥락은 짧게 유지해도 된다. 중요한 건 이미 데이터 폴더에 있다

## 실행 환경별 연결

| 환경 | 두뇌 읽기 | 기억 저장 | 대화 맥락 |
| --- | --- | --- | --- |
| 채팅 앱 + 스킬 (Claude 등) | 대화 시작 때 레포를 열고 AGENTS.md | 데이터 레포에 커밋·푸시 | 앱의 대화 기록 |
| 코딩 에이전트 (Claude Code, Codex 등) | 레포를 열면 자동 | 데이터 레포에 커밋·푸시 | 세션 기록 |
| MCP 지원 앱 (Claude 앱, ChatGPT …; `mcp_server/`) | 서버 안내문·프롬프트·리소스, 도구로 skills 읽기 | MongoDB (OAuth 토큰의 사용자) | 앱의 대화 기록 |
| 메신저 봇 (텔레그램 구현: `bot/`) | 시스템 프롬프트 = AGENTS.md + 봇 실행 규칙 + 스킬 목록, 도구 = wl · read_knowledge · user_doc_get/put | MongoDB (사용자별), 매일 데이터 git 레포로 백업 | `conversations` 컬렉션에 사용자별 최근 N개 (메신저 API는 지난 대화를 다시 주지 않음) |

## 메신저 봇의 한 메시지 처리 흐름

1. 메시지 수신 (웹훅: 즉시 200 응답 후 백그라운드 처리) → 비밀값·허용 사용자 확인 → 사용자별 잠금 (한 사람의 메시지는 순서대로)
2. 처음 보는 사용자면 `templates/`로 데이터 초기화 (운동 사전, 프로필·상태 양식)
3. 프롬프트 조립 (캐시 친화 순서): 도구 정의 → AGENTS.md + 봇 실행 규칙 + 스킬 목록 → `profile.md` ‖ 오늘 날짜 → `status.md` → 최근 대화 → 새 메시지
   - ‖ 앞까지는 거의 안 바뀌므로 프롬프트 캐시 지점(1시간)으로 둔다. 날짜처럼 매번 바뀌는 건 뒤에
4. LLM이 필요한 skill 본문을 읽고(`read_knowledge`), `wl` 도구로 기록·계산, `user_doc_put`으로 상태 갱신 — 저장은 즉시 MongoDB에
5. 사용자 말과 최종 답만 대화 맥락에 저장 (도구 중간 결과는 저장하지 않음: 필요한 건 이미 기록·문서에 있음)
6. 답장 (4000자 넘으면 줄 단위로 나눠 보냄)

## 여러 사용자

배포: [`deploy-telegram.md`](deploy-telegram.md)

- 계정: `accounts` 컬렉션. 텔레그램에서 시작하면 `tg:<ID>`, 다른 앱에서 "새로 시작하기"면 `u:<무작위>`. 연결 코드로 텔레그램과 다른 앱을 한 계정에 묶는다 (`deukgeuni_server/accounts.py`)
- 두뇌는 하나, 데이터 폴더는 사용자마다 (`WL_DATA=/data/<user_id>`)
- 또는 MongoDB 백엔드 하나에 `user_id`로 구분 (`docs/storage.md`) — 텔레그램 봇이 이 방식
